# MTL Official Product Knowledge Base

ฐานความรู้ผลิตภัณฑ์เมืองไทยประกันชีวิต โดยยึดเว็บไซต์ทางการของบริษัทเป็นแหล่งหลัก ตรวจล่าสุด 30 กันยายน 2569

## เปิดเว็บไซต์ใน localhost

```bash
npm install
npm run dev -- --host 127.0.0.1
```

จากนั้นเปิด [http://127.0.0.1:5173/](http://127.0.0.1:5173/) และใช้ `npm run build` เมื่อต้องการตรวจ production build

## Production SEO และประสิทธิภาพ

ก่อน build สำหรับโดเมนจริง ให้กำหนด `SITE_URL` และ `VITE_SITE_URL` เป็น origin เดียวกัน เช่น `https://www.example.com` จากนั้นรัน:

```bash
SITE_URL=https://www.example.com VITE_SITE_URL=https://www.example.com npm run build
npm run seo:validate
```

ระบบจะ prerender หน้าแรก หน้ารวมแผน หน้าเกี่ยวกับ/ติดต่อ และหน้ารายละเอียดสินค้า 43 หน้า พร้อม title, description, canonical, Open Graph, Twitter Card, JSON-LD, `robots.txt` และ `sitemap.xml` โดยอัตโนมัติ รูปใช้งานจริงเป็น WebP พร้อม `srcset`; ไฟล์ต้นฉบับความละเอียดสูงเก็บไว้ที่ `source-assets/images/` เพื่อไม่ให้ถูกคัดลอกไป production โดยไม่จำเป็น

## โบรชัวร์ PDF ในเว็บไซต์

เว็บไซต์เก็บ PDF ไว้ที่ `public/brochures/` เพื่อให้ปุ่มดาวน์โหลดในหน้ารายละเอียดทำงานได้โดยตรง ไม่ต้องพึ่งลิงก์ภายนอกขณะลูกค้าใช้งาน มีไฟล์ไม่ซ้ำ 42 ไฟล์ ครบทั้ง 43 การ์ดผลิตภัณฑ์ โดย 37 การ์ดใช้โบรชัวร์ทางการ 3 การ์ดใช้เอกสารข้อมูลผลิตภัณฑ์ทางการเป็นไฟล์สำรอง และอีก 3 การ์ดใช้สรุปที่จัดทำภายในเว็บไซต์จากหน้าผลิตภัณฑ์ทางการ (การ์ด D Health Lite สองรายการใช้โบรชัวร์ไฟล์เดียวกัน)

สามรายการที่ยังไม่พบ PDF ทางการ ได้แก่ `โครงการ เมืองไทย วัยเก๋า อุ่นใจหายห่วง (เพื่อผู้สูงอายุ)`, `โครงการ เมืองไทยวัยเก๋า คุ้มทั่วไทย (เพื่อผู้สูงอายุ)` และ `เมืองไทย SME 20 plus` โดยยังคงชื่อไว้ใน `no_official_pdf_found` เพื่อรักษาที่มาของข้อมูล ไฟล์สรุปที่เพิ่มให้สามรายการนี้ไม่ใช่โบรชัวร์ เอกสารกรมธรรม์ หรือเอกสารที่ออกโดยเมืองไทยประกันชีวิต และในหน้ารายละเอียดจะลิงก์กลับไปยังหน้าผลิตภัณฑ์ทางการเพื่อให้ตรวจข้อมูลล่าสุดได้

```bash
npm run brochures:sync
npm run brochures:verify
```

คำสั่งแรกดาวน์โหลดเอกสารทางการตาม manifest จากโดเมนที่อนุญาต และตรวจไฟล์ `local_summary` ที่มีอยู่โดยไม่ดาวน์โหลดทับ ส่วนคำสั่งที่สองตรวจว่าทุกไฟล์มี PDF signature ครบถ้วน

## สิ่งที่นับเป็น “43 รายการ”

หน้า All Insurance แสดง 39 การ์ดที่ลิงก์ไปยังหน้าผลิตภัณฑ์ และตะกาฟุลอีก 4 การ์ดที่ลิงก์ไปเอกสาร PDF รวม 43 การ์ด แต่มี 42 ผลิตภัณฑ์/ชุดผลิตภัณฑ์ที่แตกต่างกัน เพราะ “ประกันสุขภาพเด็ก” เป็นหน้าอธิบาย D Health Lite สำหรับเด็ก นอกจากนี้บางหน้ารวมสัญญาเพิ่มเติมมากกว่าหนึ่งแบบ

หน้า All Insurance เป็นรายการที่บริษัทนำเสนอในปัจจุบัน ไม่ใช่หลักฐานว่าเป็นทะเบียนทุกแบบที่ยังมี URL หรือทุกแบบที่ออกใบเสนอได้ แบบที่ไม่ปรากฏบนหน้านี้จึงไม่ควรถูกตีความว่าเลิกขายโดยอัตโนมัติ และแบบที่ปรากฏก็ต้องตรวจช่องทางขาย/ใบเสนอขายจริงอีกครั้ง

## ลำดับความน่าเชื่อถือของข้อมูล

1. กรมธรรม์ ตารางผลประโยชน์ และใบเสนอขายที่ออกจากระบบบริษัทสำหรับลูกค้ารายนั้น
2. โบรชัวร์/เอกสาร PDF ล่าสุดบนโดเมน `muangthai.co.th`
3. หน้ารายละเอียดผลิตภัณฑ์และหน้า All Insurance ของบริษัท
4. เว็บไซต์ตัวแทน โพสต์ หรือสื่อสรุป ใช้ได้เพียงเป็นเบาะแสและต้องตรวจย้อนกับข้อ 1–3

ไฟล์เดิม `data/muangthai-products-2026-09-30.json` และ `tools/extract_mlt_products.py` เป็น snapshot จากเว็บไซต์ตัวแทน จึงเก็บไว้เพื่อการตรวจสอบย้อนหลังเท่านั้น และไม่ใช่ฐานสำหรับคำแนะนำปัจจุบัน
